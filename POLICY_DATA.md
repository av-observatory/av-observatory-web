# Policy tracker data

`public/data/policy_tracker.json` is the reviewed, machine-readable snapshot. It contains federal FMVSS and oversight events, 50 state records plus D.C., state legislation/executive-order events and city policy events. Each event has a stable ID, jurisdiction level, instrument, status, date (null if unverified), summary, source URL and verification date. `source_tier: secondary` marks state entries whose direct legislation link still requires review. An event with `historical_status_unverified`, `rescinded`, or `completed` is not current operating authority.

The five-stage FMVSS display uses `status: under_review` after the comment deadline and `status: effective` only after a final rule's effective date. Federal entries include `comment_deadline`, `effective_date`, and links to the proposal or comment extension where applicable. The 2020 occupant-protection proposal remains in the source record alongside its 2022 final rule. The final rule has one parent record listing all 13 numbered standards amended in the Federal Register regulatory text, plus 13 individually displayed records linked to that parent by `rulemaking_id`; the 2020 proposal lists the 11 numbers in its proposed regulatory text. Changes to 212 and 219 were added in the final rule and have no individual original-proposal link. An additional 2026 FMVSS 204 final rule is tracked separately and marked `scope: related vehicle design` because its applicability change is not expressly limited to ADS vehicles. This index covers rulemakings expressly adapting FMVSS to ADS design and closely related steering-control changes, not all generally applicable FMVSS amendments (for example, ordinary seat-belt updates). For every new rulemaking, review the entire proposed and final Part 571 regulatory text, record each distinct amended standard number, check the effective and any later compliance dates, and link both stages. Search the Federal Register by NHTSA, Part 571 and ADS/steering-control terms; compare subsequent final rules and withdrawals before changing a proposal's status. Do not treat a single search result or a headline's named standard as the full list. California DMV and CPUC rulemaking milestones are individual `state_events` with stable IDs and primary agency links.

Edit the curated records in `scripts/build-policy-data.py` and state descriptions in `src/lib/statePolicySurvey.ts` / `src/lib/statePolicy.ts`, then run `npm run policy:rebuild` and review the JSON diff. The generator does not automatically infer legal changes from headlines. Add new city events to `city` and federal rulemakings to `federal`, keeping proposal and final status separate. Run `npm run build` before publishing.

## Legislative bill index

`public/data/legislation_tracker.json` is the reviewed fallback for the separate federal and state bill panels. `scripts/build-legislation-data.py` regenerates it from curated bill records; `scripts/validate-legislation-data.mjs` validates its 51 jurisdictions and bill links. The state snapshot records pending bills in NCSL's September 15, 2026 AV legislation database; the federal entries link to 119th Congress bills and official GovInfo text. It is an indexed starting point, not a claim that every AV-related proposal has been found or that a listed bill is still pending today. An empty state panel means there is no pending bill in this snapshot. Each panel displays its review date and links to the underlying repository.

The bill JSON includes `measure_type` (`bill` or `resolution`) and `progress_stage` (`introduced`, `committee`, `floor`, `passed_legislature`, `executive`, or `law`), dated `stage_dates` when verified, and `hearings` only when a dated calendar entry is supplied. The six-stage display labels these Introduced, Committee, Floor Action, Passed, Executive Action, and Enacted. Here “Passed” means final legislative approval, not a new law; “Enacted” means the bill became law through signature, approval without signature, or an override. A law's effective date may be later. The seeded snapshot supports committee referral and one bill sent to the governor, but does not assert a hearing date without a documented event. The daily LegiScan refresh reads its structured `progress` and `calendar` arrays and links any listed hearing to the bill record. It does not infer that a scheduled hearing occurred or that a merely passed bill became law. Bills halted by veto or failure retain that status rather than appearing as enacted. Resolutions such as Pennsylvania HR 563 use a shorter Introduced–Committee–Adopted indicator; they are not represented as bills that can be signed into law.

For ongoing updates, configure repository secret `LEGISCAN_API_KEY` from LegiScan's free public API, repository variable `LEGISLATION_R2_PUBLIC_URL` ending in `/policy/legislation_tracker.json`, and the R2 settings below. The scheduled `legislation-refresh.yml` searches current sessions nationally for AV terms each day, fetches bill details, validates the resulting JSON, then replaces the R2 bill object. The page fetches R2 at runtime; if credentials are absent or R2 fails, it shows the dated reviewed snapshot. The refresh retains human-reviewed summaries for known bills and marks new descriptions as machine-indexed: read linked bill text before relying on a new summary. Review search terms and false positives periodically. A page deployment seeds R2 only if its bill object does not yet exist, so an older snapshot cannot overwrite a newer refresh.

## R2 configuration

The site fetches the public R2 object at runtime when `NEXT_PUBLIC_POLICY_R2_URL` is set at build time. It falls back to its bundled snapshot if R2 is unavailable. GitHub Actions uploads the validated JSON after a successful build when these repository settings exist:

| GitHub setting | Value |
| --- | --- |
| Variable `POLICY_R2_ACCOUNT_ID` | Cloudflare account ID |
| Variable `POLICY_R2_BUCKET` | R2 bucket name |
| Variable `POLICY_R2_PUBLIC_URL` | Public HTTPS URL ending `/policy/policy_tracker.json` |
| Secret `POLICY_R2_ACCESS_KEY_ID` | R2 S3 API token access key |
| Secret `POLICY_R2_SECRET_ACCESS_KEY` | R2 S3 API token secret |

Create the bucket and public custom domain, grant the API token write access to the bucket, then allow the GitHub Pages origin in its CORS policy for `GET`. Rerun the Pages workflow to upload `policy/policy_tracker.json`. The UI identifies whether R2 or the bundled snapshot supplied the visible record. Without these settings, the site publishes the JSON snapshot but does not store it in R2.
