# Multi-state bill data spec (StateTrack)

Goal: for each of WA, OR, MA, DC, FL produce, for the 2025-26 session, the same four files that `scripts/extract-ca-legislature.py` produces for California, written to `data-state/states/<ST>/`. A shared tagger (`scripts/tag-bills-taxonomy.py`) and site generator (`statetrack/scripts/build_site.py`) read them, so the SCHEMA BELOW IS A CONTRACT. Read `data-state/states/CA/*.json*` (sample entries) and `scripts/extract-ca-legislature.py` first.

## Files (all UTF-8; json.dump with ensure_ascii=False)
### bills.json  -> {"<key>": bill, ...}
key = "<TYPE> <NUMBER>" e.g. "HB 1210", "SB 5", "H 4", "B26-0005". Must be unique within the state. If a state has two separately numbered sessions in scope (FL 2025 and 2026, OR 2025R1 and 2026R1), append " (<year>)" to EVERY key of that state, e.g. "HB 1001 (2025)". Include ONLY bills/resolutions introduced in the 2025-26 period (WA biennium 2025-26; OR 2025 regular + 2026 regular, add special sessions if present; MA 194th General Court; FL 2025 and 2026 regular sessions; DC Council Period 26). For WA collapse substitute/engrossed versions to ONE record per bill number (e.g. "2ESHB 1210" -> key "HB 1210", keep the latest version's title/summary). Include resolutions/memorials (they get tagged as ceremonial) but NOT amendments or companion duplicates.
bill fields (all required unless marked optional; use "" / [] when unknown, never omit):
- id (string, any unique string, e.g. source id), type (prefix, e.g. "HB"), number (int if numeric else string), session (string, e.g. "2025")
- title (official title or short title, string)
- digest (the BEST OFFICIAL plain-language summary/abstract/digest/synopsis/long title text, up to ~3500 chars, whitespace-normalized, HTML stripped; "" only if the state truly offers none; if the only text is the long title, put that and set digest_source accordingly)
- digest_source (short string: where digest came from, e.g. "WA bill digest/summary", "OR measure summary", "MA bill summary", "FL bill summary", "DC committee/legislative summary")
- status (NORMALIZED, exactly one of: "Chaptered" (became law, signed or without signature), "Vetoed", "Passed" (passed both chambers, not yet acted on by executive), "In Floor Process", "In Committee Process", "Pending Referral", "Died" (session over without enactment / failed / withdrawn / indefinitely postponed), "Failed Passage in Committee")
- status_raw (the state's own status text), last_action (text), last_action_date (YYYY-MM-DD)
- house (chamber of origin or current: "House"/"Senate"/"Council" etc. the state's own chamber names), location_name (optional text)
- chapter (e.g. "2025 ch. 415" or "Chapter 12, Laws of 2025"; "" if not law), chaptered (bool)
- url (canonical public page for the bill)
- authors: list of {"legislator": "<legislator id from legislators.json or null if unmatched>", "name": "Last name or full name as given", "role": "LEAD_AUTHOR" | "PRINCIPAL_COAUTHOR" | "COAUTHOR", "house": chamber name}. Primary sponsor = LEAD_AUTHOR (if the state names several primary sponsors, all LEAD_AUTHOR). Other sponsors = COAUTHOR (use PRINCIPAL_COAUTHOR only if the state distinguishes a second-tier sponsor). Committee-sponsored bills: leave authors [] and put the committee name in "sponsor_committee".
- action_count (int)
### legislators.json -> {"<id>": legislator}
legislator: {"id", "name" ("Last, First"), "first", "last", "party" ("DEM"/"REP"/"IND"/other uppercase code), "house" (chamber name), "district" (string as the state labels it, e.g. "17", "Ward 3", "At-Large"), "active": bool, "url": optional}. ids: "<ST>:<chamber letter><district>" is fine if stable and unique (include session year only if a member can appear twice). Include every member who served in 2025-26 (active false for resigned/replaced).
### votes.json.gz -> {"<bill key>": [vote, ...]} (gzip JSON)
vote: {"date": "YYYY-MM-DD", "chamber": "House"/"Senate"/"Council"..., "floor": true for final-passage-type floor votes of the whole chamber (second/third reading, concurrence, passage, council first/second reading votes); false for committee votes, "motion": text, "ayes": int, "noes": int, "abstain": int (not voting/excused/absent count), "result": text, "members": {"<name as printed>": {"legislator": "<id or null>", "vote": "AYE" | "NOE" | "ABSTAIN"}}}. Committee votes: include only if easy; floor votes are required where the state publishes roll calls. If a state publishes no roll calls machine-readably, write {} and say so in the report.
### history.json.gz -> {"<bill key>": [[date, seq, "action text"], ...]} (gzip JSON), oldest first.

## Source rules
- The sandbox CANNOT reach state sites. ALL fetching must run in a GitHub Actions workflow (workflow_dispatch) on `ubuntu-latest`, which commits results with `bash scripts/commit-ledgers.sh "<message>"` (set COMMIT_PATH=data-state/states/<ST>), see `.github/workflows/extract-ca.yml` and `scripts/live-commit.sh` for the pattern; commit progress periodically so partial runs are not lost. Be polite: UA string, concurrency <=4-6 requests, retry with backoff, honor 429/Retry-After. Prefer official bulk/API/OData/XML services over HTML scraping; use HTML only for what the APIs lack. Reuse the existing endpoints in `scripts/bill_enumerators.py` for the state (functions wa/orr/ma/fl/dc) to learn what is reachable, but do not modify that file (another agent owns it); import from it if useful.
- Workflow file: `.github/workflows/extract-<st lowercase>.yml`; script: `scripts/extract-<st lowercase>-legislature.py`; outputs only under `data-state/states/<ST>/`. Also write `data-state/states/<ST>/extract_report.md`: counts (bills, with digest, with authors, by status, votes bills, legislators), the sources used, known gaps.
- No secrets in code or logs. No pull requests; push to main (`git pull --rebase origin main` before each push; other agents and bots push often; only add your own files).
- Do NOT touch: `scripts/tag-bills-taxonomy.py`, anything for CA, `data-state/taxonomy`, bill_enumerators.py, scan_fetch.py, other states' files, or the statetrack repo.
- Verify before reporting: run py_compile; after the Actions run, load your outputs and check schema (script `scripts/check-state-extract.py <ST>` will exist; if it does not yet, validate yourself): every bill has all fields; statuses within the enum; digest coverage; authors match legislators where possible; vote tallies equal member counts.
